# 文件管理器（File Manager）

在 PI-Desktop 的**右侧工作面板**里浏览并编辑当前项目的文件。它不是宿主内置「文件」视图的替代品，而是并列的一行：内置视图只读，这一行可编辑。

源码仓库：<https://github.com/Tioit-Wang/pi-desktop-plugin-file-manager>

## 为什么做这个

宿主内置的「文件」视图只能看不能改，而宿主的 `pi.fs` 网关在语法上就**禁止整树写入**（`manifest.fs` 的 write scope 不能是 `**`），任何一个能通过校验的窄 scope 都会让「保存」变成每次都弹权限确认；`pi.fs.*` 也没有创建 / 重命名 / 移动能力。

所以这个插件在自己的进程里用 Node `fs` 读写当前项目，并**自己承担全部安全责任**（见下面的「安全」一节）。

## 功能

- **完整目录树**：懒加载、目录优先、键盘导航（↑↓ Home End ←→ Enter）；每一行的图标随文件类型变化——文件夹、代码、JSON、Markdown、样式、HTML/Vue/Svelte、YAML/TOML、Shell、SQL、图片、压缩包、字体、锁文件等各有字形与配色，`package.json` / `Dockerfile` / `LICENSE` / `.gitignore` 这类特殊文件名优先于扩展名判定。
- **选中态与悬停态明确区分**：悬停是淡中性底色；选中是强调色底 + 左侧强调色竖条 + 前景色文字 + 中等字重，鼠标移开也保持。
- **右键菜单**：在文件 / 文件夹上右键可新建文件、新建文件夹、重命名、移动、打开、刷新；列表空白处右键提供「在此新建」与刷新。
- **左右分栏**：左侧文件列表，右侧内容；分隔条可拖拽，宽度会记住。
- **代码高亮编辑**：CodeMirror 6，行号、查找替换、多光标、括号匹配、代码折叠。按文件名加载语法高亮，覆盖 TypeScript/TSX、JavaScript/JSX、JSON、Markdown、CSS/SCSS/Sass/Less、HTML、Vue、XML、YAML、TOML、Properties、Python、Go、Rust、Java、C/C++、C#、Kotlin、Scala、Dart、Objective-C、PHP、Ruby、Lua、Shell、PowerShell、SQL、Dockerfile、Diff。全部随包内置、离线可用。`Ctrl/Cmd+S` 或工具栏按钮保存。
- **Markdown 预览 / 编辑切换**：打开 `.md` / `.markdown` / `.mdx` 时工具栏出现切换。预览支持标题、围栏代码块（复用编辑器同一套高亮）、引用、分隔线、有序/无序/任务列表（按缩进嵌套）、表格（含对齐）、行内 code / 粗体 / 斜体 / 删除线 / 链接 / 图片；切换会记住。
- **按文件名搜索**：整个项目范围内分页搜索，点击结果直接跳转并展开定位。
- **忽略规则**：项目里有 `.gitignore` / `.ignore` 就按规则隐藏条目（工具栏眼睛按钮可切回显示）；**一个规则文件都没有时，目录树展示全部条目**。
- **跟随宿主外观**：亮 / 暗配色与界面语言（中文 / English）跟随 PI-Desktop 主体，编辑器与预览的高亮配色一并跟随。

## 安装

在 PI-Desktop 的 **插件 → 市场** 中安装；或下载 `packages/pi.file-manager-0.2.0.piplug` 后走 **Install plugin package**。

装好后打开一个项目，在**右侧工作面板头部的切换菜单 →「Plugin views」分组**里点击「文件管理器」。

> 这个插件没有命令面板入口，也不注册独立面板窗口——它只提供一个停靠在右侧栏的视图（`contributes.views`）。宿主没有提供「用命令打开视图」的通道，所以这里也不声明误导性的命令。

## 权限

只申报一项：

- `ui.view` —— 把视图停靠到右侧工作面板。

**为什么没有申报 `fs.read` / `fs.write`**：宿主 `manifest.fs` 在语法上无法表达「整树写入」，任何一个能通过校验的窄 scope 都会造成「写入受限」的假象，比不申报更危险；而 `fs.read` 本插件从不使用（不调用任何 `pi.fs.*`）。真实触达写在 `i18n.*.safetyNotes` 与本文件的「安全」一节，这是当前唯一能诚实表达它的位置。

无网络：`manifest.json` 没有 `net.domains`，运行时不发起任何请求。插件数据目录只保存设置（分栏宽度、显示开关、Markdown 默认视图）和一份写入审计日志。

## 安全

文件读写**由插件自身**限定在项目根目录内，宿主的权限网关不介入这些调用。插件实施的全部限制：

| 限制 | 说明 |
|---|---|
| 路径包含 | 只接受相对项目根的路径；绝对路径、`..`、以及 realpath 后落到根目录之外的**符号链接 / junction** 一律拒绝 |
| 敏感路径 | `.env*`、`.ssh`、`.aws`、`.gnupg`、`.git/**`、`*.pem`、`*.key`、`*.p12` 等读写全拒；`node_modules` 可读不可写 |
| 原子写 | 先写同目录临时文件 → `fsync` → 保留原文件权限位 → `rename` 覆盖，中断不会留下半写文件 |
| 冲突检测 | 以 `mtimeMs` + 文件大小作为乐观锁；文件在编辑器之外被改动过时**不会静默覆盖**，会先弹对话框让用户选择覆盖 / 放弃 / 重新加载 |
| 写入审计 | 每次写入追加一行到插件数据目录的 `write-audit.jsonl`（约 1 MiB 后轮转），因为宿主审计不到这条路径 |
| 体积上限 | 预览 2 MiB、写入 8 MiB；二进制文件与图片不进入编辑器，只提示 |

Markdown 预览**不使用** `dangerouslySetInnerHTML`，而是把 Markdown 解析成 React 元素——节点由 React 转义，结构上不存在注入面，因此也不需要额外的 sanitizer。预览中的链接不会导航（点一下就离开插件页面回不来了），点击只会把地址显示出来。

行为说明：`.git` 目录不会出现在树里；忽略规则是 gitignore 的一个子集（支持 `!` 取反、末尾 `/`、前导 `/` 锚定、`*` / `?` / `**`，不支持 `\` 转义与 `[a-z]` 字符类），偏差只影响「显不显示」，随时可用工具栏的眼睛按钮翻盘。

## 已知限制

- **不删除文件 / 目录**：删除是破坏性操作，且宿主的 `fs.remove` 并未开放给视图桥，只能走原生 `rm`——本期不做。
- **没有「在文件夹中显示」/「用系统程序打开」**：这两个宿主通道需要 `fs.read` 权限，而本插件有意不申报任何 fs 权限。
- **预览里的图片不加载**：面板以 `file://` 加载，相对路径指向视图自身而不是项目，因此图片显示为带文件名的占位块，而不是破图。
- **文件监听**：宿主没有「插件 → 视图」的推送通道（视图只能发起请求、拿响应），外部改动不是实时的；保存后会自动刷新，工具栏也有手动刷新。
- 二进制与图片不可编辑，也不做图片预览（与宿主内置的「文件」视图一致）。

## 构建

本目录只包含可直接运行的产物（`main.js` + `views/`）。视图源码（React + TypeScript + Tailwind + CodeMirror 6）与构建脚本在源码仓库的 `views-src/`：

```bash
cd views-src
pnpm install
pnpm typecheck
pnpm verify      # 语法高亮 + Markdown 预览的离线校验
pnpm build       # 产物输出到 ../views
```
